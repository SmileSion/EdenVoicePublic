# 房间聊天记录持久化

## 存储与显示

- 服务端按房间追加写入 `security.data_dir/chat/<房间ID>.jsonl`，默认目录是 `data/chat/`。每一行是一条完整 JSON 消息，换行、表情等文本由 JSON 转义。
- 消息保存成功后才加入最近记录并广播。服务器重启后，从文件尾部读取各现存房间最近 100 条，不扫描或加载整段历史正文。
- 服务端每个房间缓存最多 100 条；客户端实时核心每个房间也最多 100 条，并保留原有跨房间总缓存 500 条上限。支持新协议时，界面可按需分页读取更早记录并搜索服务端历史，详见[日常使用优化](daily-experience.md)。
- 超出缓存上限的消息不会从日志删除。删除房间也不删除对应日志；全局消息 ID 恢复会考虑这些房间，避免重启后复用旧消息 ID。
- 房间 ID 的历史最高值也会持久化，删除房间或临时房间消失后不再复用 ID，避免新房间继承旧房间的聊天日志。
- 时间以服务端 Unix 毫秒时间戳保存，客户端按本地时区显示 `YYYY-MM-DD HH:mm`。历史消息的自身归属使用稳定 ClientID，不使用重启后可能复用的会话 ID。

## 语音隔离与失败处理

写盘和同步发生在文字消息处理路径，使用独立聊天锁保证消息顺序，期间不持有语音转发共用的状态锁，也不修改音频回调、编解码或混音。

每条消息追加后执行文件同步。保存失败时返回发送错误，不缓存或广播未确认保存的消息。若出现部分写入或同步结果不确定，本进程停止继续追加，避免覆盖、拼接损坏的历史。同步失败时磁盘仍可能存在一条未确认发送的完整记录，这种情况下重启后可能看到它。

启动时如遇日志不完整、读取失败等问题，会保留原文件并记录错误，禁用本进程聊天发送，语音服务继续运行；不会静默清空历史或回退到内存存储。需要管理员备份原始文件后检查磁盘、权限或不完整的末尾记录，处理后重启。不会自动截断或删除损坏的数据。

日志不自动清理，磁盘用量随历史增长，请安排备份和空间监控。容器部署需要挂载持久数据卷。建议停服后备份整个数据目录。

## 升级注意

此功能需要更新服务端才能持久化，并更新客户端才能显示完整日期及执行客户端每房间 100 条上限。协议沿用现有聊天消息格式。

旧版本未写入磁盘的聊天记录无法自动恢复；从启用持久化后接收的消息开始保存。较早记录的读取需要支持 `chat_query_v1` 的服务端和客户端，查询不会改变原日志。

## 自动验证

- `server`: `mise exec -- go test -race ./...`，覆盖重启后最近 100 条、完整历史保留、消息 ID 连续恢复、末尾读取量上限、异常文件不被修改、慢磁盘不锁住语音状态、写入失败不发布。
- `client`: `CMAKE_POLICY_VERSION_MINIMUM=3.5 mise exec -- cargo test --lib`，覆盖历史批量加载和实时消息的每房间 100 条限制、排序、去重。
- `desktop`: `npm run test:chat` 与 `npm run build`，覆盖跨年/闰日日期显示和持久化消息身份判断。
