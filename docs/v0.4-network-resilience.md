# V0.4 Weak Network and Network Resilience

V0.4 preserves the V0.3 SFU-first admission path and qualified P2P optimization. It adds a weak-network feedback loop without introducing a long-lived hybrid topology.

## Implemented architecture

- `NetworkQualityEngine` combines effective audio loss, burst length, RTT, jitter, receiver underruns, resyncs and route health. Degradation is faster than recovery and state changes use hysteresis plus minimum hold time.
- Receivers generate per-peer `audio_qoe_feedback` every 500 ms. The server validates room membership and forwards feedback through the existing TCP control plane to the relevant sender.
- `AudioAdaptationController` maps GOOD/FAIR/POOR/CRITICAL to Opus bitrate, in-band FEC, expected loss and DTX. Fixed quality preserves the selected bitrate while FEC and loss expectation remain adaptive.
- `JitterBuffer` changes its target prefill between 3 and 8 frames and can discard stale packets during resync. Opus PLC remains active for missing frames.
- `RoomNetworkPolicy` is independent from current transport. `force_p2p` starts on SFU, enters `p2p_pending` until qualified, uses temporary SFU recovery after P2P failure, and retains the policy while requalifying.
- `WeakNetworkSimulator` provides deterministic random loss, burst loss, blackout, reordering, RTT and jitter profiles for repeatable unit tests.

## Network stabilization

- Adaptive UDP no longer drops reordered packets at a transport-level high-water mark. Duplicate, late, wraparound and reordering decisions remain owned by the per-peer jitter buffer.
- Unqualified direct candidates are probed in bounded rotating batches. After a route qualifies, the client probes the selected route at the stable cadence instead of every advertised endpoint.
- Client media datagrams reuse an encode buffer, and the Go relay parses payloads as views into its receive buffer before forwarding the original datagram.
- Control commands/events and each server connection use bounded queues. A slow control consumer is disconnected instead of blocking room-wide broadcasts or growing memory without bound.
- Network reports must target a current member of the same room and contain bounded finite metrics. Reports and subscriptions are cleared when either peer moves, leaves, or disconnects.
- Route updates are broadcast only when the evaluated room route changes.

## Acceptance matrix

| Area | Required behavior |
|---|---|
| AUTO quality | Bitrate steps 64 → 48 → 32 → 24 kbps as quality degrades; recovery requires a longer stable window. |
| FIXED quality | Selected 24/32/48/64 kbps is retained; FEC, expected loss, jitter handling and route recovery remain active. |
| FORCE_SFU | Qualified P2P candidates never change the stable room topology. |
| FORCE_P2P | SFU admission → P2P pending → P2P stable; P2P failure → temporary SFU → background P2P recovery. |
| Hard guardrail | Unsupported room size or disabled P2P returns `p2p not supported for current room`; policy is not silently changed. |
| Loss resilience | Random/burst loss, late packets, reordering and stale packets are counted separately; missing audio uses PLC and stale audio is discarded on resync. |
| Short interruption | Control reconnection retains desired channel and network policy; media restarts without a user-driven leave/join cycle. |

## Test commands

```bash
cd client && cargo test --all-targets
cd server && mise exec -- go test ./...
cd server && mise exec -- go test -race ./...
```

Socket-based Rust tests require permission to bind loopback ports. In a restricted sandbox, run the pure unit matrix with `cargo test --lib network::tests` and `cargo test --lib jitter::tests`.
