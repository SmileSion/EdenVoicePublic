# EdenVoice V0.5 人工发布验收

本清单只覆盖自动化测试无法证明的真实 GUI、声卡、可听质量和长时间资源表现。
每项记录测试时间、客户端机器、网络环境、结果和异常截图；不要把服务器密码、
MASTER Token、客户端私钥或身份文件写进记录。

## 准备

- 使用 `dist/v0.5.0/EdenVoice-v0.5.0-macos-arm64.zip` 中的同一发布构建。
- 准备两个相互独立的客户端身份。不同电脑或不同 macOS 用户账户天然使用不同
  配置目录；同一账户启动两个进程会共享 ClientID，只适合验证同身份多会话，
  不适合验证角色授权。
- 服务器填写 `203.0.113.11:7001`，语音端口由服务端下发。
- 一端使用 MASTER，另一端保持 USER；需要时再把 USER 提升为 ADMIN 或
  CHANNEL_ADMIN。
- 建议耳机测试，避免扬声器回灌影响回声消除和可听判断。

## A. 首次信任、重连与语音

1. 两端首次连接，核对都出现服务器指纹确认，确认后进入主界面。
2. 断开并重新连接同一地址，确认不再重复询问指纹。
3. 单击频道，只应选中；双击后才应进入频道。
4. 双方连续交替说话至少两分钟，再同时说话 30 秒。
5. 分别切换自静音、扬声器静音和按键说话。

通过标准：连接和身份认证通常在数秒内完成；第二次连接无信任提示；单击不换房，
双击才换房；双方语音清晰，无持续爆音、卡死、单向无声或异常重连。

## B. 管理与权限

由 MASTER 对 USER 依次执行并记录可见结果：

1. 创建顶层频道、创建子频道、改名、删除；删除有成员的频道时成员应安全移出。
2. 从频道右键设置 `自动`、`强制 SFU`、`强制 P2P`。
3. 管理员禁言 USER：USER 的麦克风按钮应变橙并出现锁标记，点击或快捷键都不能
   打开采集；解除后恢复正常控制。
4. 移动 USER、踢出频道、踢出服务器；被踢端应显示明确原因且停止自动重连。
5. Ban USER：所有该 ClientID 的在线会话都应断开；Ban 管理页可见记录，Unban
   后允许重新连接。
6. 设置/取消 ADMIN，设置/取消 CHANNEL_ADMIN；CHANNEL_ADMIN 只能管理授权
   范围内的房间，不能管理 MASTER/ADMIN。
7. 尝试对自己执行踢出频道、踢出服务器和 Ban，客户端不应提供可执行操作，服务端
   也不得接受绕过请求。

通过标准：每个操作立即反映到两端界面；越权项不可执行；客户端重连后角色、频道、
频道管理员和 Ban 状态仍保持。服务重启持久化已由自动化覆盖，不在生产人工验收中
主动重启服务器。

## C. SFU/P2P 与弱网

1. 在同一频道先选择强制 SFU，连续通话一分钟并记录网络详情。
2. 切换强制 P2P，观察 `SFU → HYBRID/评估 → P2P`，继续通话一分钟。
3. 通话中制造受控丢包、抖动或短暂断网，观察自动回退 SFU；网络恢复后观察重新
   评估 P2P。
4. 在双方持续读数或播放固定语句时完成来回切换，避免只看状态标签。

通过标准：安全上下文准备完成前不切换媒体；切换期间没有明显长断音、持续重复音、
异常加速或永久单向无声；弱网时能回退并恢复。

## D. 长时间真实会话

本次 v0.5 发布门槛运行一小时；用户于 2026-08-26 根据实际体验明确接受一小时
作为本轮长时验收时长。推荐后续版本或容量测试继续覆盖两小时及游戏等正常前台
负载。每 15 分钟记录一次：

- 活动监视器中的 EdenVoice CPU 与内存；
- 网络详情里的 RTT、丢包、抖动、上下行速率和错误提示；
- 当前降噪模式和音频设备；
- 是否出现爆音、断音、延迟持续升高或快捷键失效。

可在开始通话后用发布客户端的进程 PID 自动记录 CPU 与 RSS（KiB）：

```bash
./scripts/capture-client-soak.sh --pid <EdenVoice-PID> \
  --duration 3600 --interval 900 \
  --output ./edenvoice-v0.5-soak.csv \
  --note "macOS / 耳机 / 双客户端"
```

脚本会立即采样，此后每 15 分钟采样，并在进程提前退出时记录 `exited` 后停止。
备注中不要填写服务器密码、MASTER Token、私钥或身份文件内容。音频异常、设备切换、
降噪切换、断线重连和 SFU/P2P 往返仍需在结果表中记录准确时间，便于和 CSV 对齐。

期间至少完成一次音频设备切换、一次降噪模式切换、一次断线重连和一次
SFU/P2P 往返。通过标准：RSS 不呈持续单调增长，空闲 CPU 不异常，界面保持响应，
没有持续 20 ms 音频截止时间告警或队列饥饿，重连后身份和频道恢复正确。
