# 性能优化与独立更新说明

本轮不部署、不推送，也不修改语音协议、编码码率或降噪配置。

| 优化 | 更新范围 | 兼容性与收益 |
| --- | --- | --- |
| 按房间维护接收者索引，来源验证不克隆完整会话 | 仅服务端 | 老客户端可继续使用；减少全服在线人数增加带来的查找成本 |
| 出站语音封包缓冲池、批量发送描述符复用 | 仅服务端 | 老客户端可继续使用；减少临时堆分配，缓冲区发送或丢弃后才归还 |
| UI 快照节流、字段增量 IPC、保留未变数组引用 | 仅客户端 | 兼容原服务端；桌面原生端和前端随客户端一起更新 |
| 显式麦克风静音时告知 WebRTC 输出不使用 | 仅客户端 | 兼容原服务端；标准 WebRTC 模式减少计算，仍持续维护回声处理状态 |

没有任何一项要求客户端、服务端同步升级。可以先只更新服务端，再逐步更新客户端。

## 实现边界

- UI 主窗口可见或有迷你浮窗时，快照周期为 100ms；隐藏/最小化且无浮窗时为 500ms。用户命令可立即触发刷新，核心处理循环及音频线程节奏不变。
- 增量快照带基础版本号。启动和版本缺口通过完整快照恢复；聊天、成员等未变化字段不反复序列化和传输。
- 房间成员索引随进入、离开、断开及删除房间迁移维护；静音/拒听、订阅与传输资格仍读取当前状态。
- 仅复用可安全拥有的出站缓冲及批量描述符；加密等步骤仍可能分配内存，不能称整个转发链路零分配。
- 麦克风测试、DSP 切换过渡不进入输出闲置状态。RNNoise/DeepFilterNet 保持模型热状态，本次不跳过神经网络推理；按键发言松开或 VAD 静默也不触发此优化。

## 自测

- Go 服务端全包测试通过；serverstate、voice、protocol 竞态检查通过。
- Rust 客户端库：244 项通过，1 项既有五分钟压力测试忽略。
- 桌面原生库：32 项通过；增量快照专项复测通过。
- 桌面前端构建通过；快照合并、事件订阅与版本缺口恢复测试通过；共同观影浏览器集成测试通过。
- UDP 回环按 20ms 节奏发送 10 帧、每帧 4 个输出，共 40 包全部收到，无排队丢弃或过期；验证负载内容和顺序。
- 补充缓冲区发送/过期回收、顺序发送回退的所有权测试。

## 局部基准（本地 Apple M5）

| 场景 | 原方式 | 优化后 |
| --- | --- | --- |
| 全服 2 人，目标房间 2 人，接收者查找 | 76.87 ns/op | 73.65 ns/op |
| 全服 1000 人，目标房间 2 人，接收者查找 | 6343 ns/op | 76.45 ns/op |
| 240 字节语音负载封包 | 37.78 ns，288 B，1 次分配 | 10.20 ns，0 B，0 次分配 |
| 标准 WebRTC DSP，每 20ms 音频帧 | 247.506 μs | 显式静音 214.980 μs |

DSP 数据来自开发构建的合成音频微基准，约减少 13% 的该步骤耗时，不代表整个客户端 CPU 降低同等比例。查找加速也不代表整机提升同等倍数。

不节流的并发洪泛基准会触发有界队列主动丢弃（本机约 94–97%）；测试分别统计已转发、排队丢弃、过期丢弃，不能据此宣称真实通话容量。上述回环测试也不是长时间多人外网通话验证。本轮未部署线上，未重新进行 Windows 实机长时间通话。
