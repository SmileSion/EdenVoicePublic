# EdenVoice v0.8.5

## 本版变化

- 屏幕共享服务端改为独立固定 UDP 端口，默认 `7010`。各房间与观看连接复用该端口，保留独立身份校验、加密会话与观看者发送队列。
- 不改变原有语音 UDP 端口、编码、抖动缓冲和 P2P / SFU 路由策略。简化端口配置不会直接降低媒体码率或保证公网不卡顿。
- 客户端、服务端、应用内版本标签和构建元数据统一为 `0.8.5`；英文与中文 README 补充单端口部署和升级说明。

## 升级配置

在已有 `[screen_share]` 段中把端口范围改为：

```toml
udp_port = 7010
```

保留自己的 `enabled`、`public_ip`、画质和容量设置，删除旧的 `udp_port_min`、`udp_port_max`。过渡期间，如果没有 `udp_port`，服务端沿用 `udp_port_min` 作为唯一端口；如果同时存在，新字段优先。

放行对应 UDP 端口；Docker 映射示例为 `-p 7010:7010/udp`。备份并保留数据目录，替换服务端二进制后重启，确认屏幕共享可用再删除旧范围其余端口的放行规则。重启会断开正在进行的会话；客户端重新连接后，共享需要重新发起。

## 客户端兼容

只更新服务端即可启用端口复用。已支持屏幕共享的客户端通过 WebRTC SDP / ICE 协商获得端口，无需为这次变更升级；不支持共享的旧客户端仍可使用语音。客户端版本号更新不代表已经发布新安装包，下载清单应保留真实可下载的版本，待安装包上传后再更新并下发。

## 使用与测试说明

房间内一位分享者、其他成员主动观看，不同房间可以在服务器策略允许的容量内并发共享。观看仍在客户端的屏幕标签页中进行，支持自适应尺寸和全屏。后台画质限制与观看人数设置沿用原有逻辑。

屏幕共享使用独立媒体连接和有界队列，但与语音共享服务器出口带宽。建议按实际带宽配置画质与观看人数；不能根据端口数量推算承载人数。

原生平台边界、使用方式与历史模拟验收记录见[屏幕共享说明](screen-sharing.md)。macOS 系统声音要求 14.2+；Windows 系统声音可能包含通话回放，默认关闭。代码、浏览器和本机合成媒体测试不能代替 Windows 原生采集及跨设备公网验收。

## 本版回归验证

- 全量 `go test ./...`、`go vet ./...` 通过；共享、配置、Web 管理包的竞态检测通过。
- 两个房间、两个发布者与三个观看者的实际 SRTP 转发通过：所有服务端候选使用同一端口，房间负载隔离，停止某个观看者或房间后其他连接仍收到新包。
- 覆盖禁用启动、端口占用、启用失败不落盘、存盘失败回滚、关闭释放端口、IPv4 公网映射及 IPv6 收发。
- Chrome 合成画面与音轨经真实 WebRTC 编解码通过，声音开启 / 关闭 / 恢复及停止清理通过；同期五人合成语音应收 3640 包、实收 3640 包。
- 前端生产构建、15 项屏幕共享控制器测试、更新交互浏览器回归及 Rust 锁定依赖元数据校验通过。

本机媒体测试使用回环地址，避免依赖宿主机局域网自连策略；无头浏览器使用虚拟音频输出维持时钟，但仍检查真实 Opus/RTP 音轨和解码能量。以上结果不等同于真实设备采集或公网流畅度保证。

另提供按需执行的部署检查 `TestLiveScreenShareFixedPort`：设置 `EDENVOICE_SCREEN_CONTROL`、`EDENVOICE_SCREEN_FINGERPRINT`、`EDENVOICE_SCREEN_CHANNEL` 与 `EDENVOICE_SCREEN_PORT` 后，运行 `go test ./cmd/voice-smoke -run '^TestLiveScreenShareFixedPort$' -count=1 -v`。请选择空闲房间；检查使用已认证控制连接验证固定端口、合成 SRTP 负载及停止清理，不采集真实屏幕或声音。
