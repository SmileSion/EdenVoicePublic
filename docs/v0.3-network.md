# V0.3 Network Architecture and Acceptance

## Runtime model

V0.3 uses SFU-first routing. `WELCOME` starts the UDP SFU path immediately; candidate discovery never blocks audio readiness. All usable same-family interface addresses, IPv6, and server-reflexive IPv4 pairs are probed concurrently from the same media socket. During discovery the client sends a short 75 ms probe train, tries a bounded `±2` port window around server-reflexive mappings, learns the peer-reflexive port actually observed when NAT rewrites it, and relaxes to a 500 ms keepalive after qualification. A direct route must continuously satisfy RTT `<80 ms`, loss `<2%`, and jitter `<15 ms` for 1.5 seconds. Only a complete directed qualification matrix permits the room to become `P2P_STABLE`.

Stable room states are `SFU_STABLE` and `P2P_STABLE`. `P2P_EVALUATING`, `TRANSITIONAL_HYBRID`, and `MIGRATING_TO_SFU` are temporary. When a member joins a P2P room that remains eligible, existing direct routes stay active while every client also sends the stream through the warm SFU path. Rooms above `p2p_max_room_size` switch to SFU instead of building an oversized full mesh. A failed qualified route reports degradation after 1.5 seconds without acknowledgements; qualification uses the strict RTT/loss/jitter thresholds while an established route uses the wider `route_degrade_*` thresholds to avoid flapping.

The UDP server is a packet SFU: one publisher stream per session, explicit optional subscriber sets, authoritative room isolation, no Opus decoding, and no server mixing. An empty subscription set means “subscribe to all room publishers” for V0.2 compatibility. Relay uses the same bound UDP port and validation path but is a compatibility route selected by the control policy.

## Configuration

`server/config.example.toml` documents all routing values under `[network]`: enable flags, room eligibility sizes, qualification/dwell/cooldown/degrade durations, quality thresholds, and bounded media queue size. Only TCP 9000 and UDP 9001 are required.

## Local test

1. Run `cd server && go run ./cmd/voice-server --config config.example.toml`.
2. Run two release clients and join the same channel. Audio should become Ready immediately with `P2P_EVALUATING / SFU` in Diagnostics.
3. Leave both clients connected for about two seconds. On a healthy local network Diagnostics should converge to `P2P_STABLE / P2P`.
4. Join a third client. Existing clients should show `TRANSITIONAL_HYBRID`; all three remain audible while qualification restarts.
5. Select Force SFU and Force Relay in Diagnostics and verify bidirectional speech. Return every member to Auto before P2P qualification testing.

## Public-network test

Deploy the single Docker image with `-p 9000:9000/tcp -p 9001:9001/udp`. Connect one client through home broadband and one through a mobile hotspot. Confirm server logs show UDP registration and candidate exchange, then observe whether the route qualifies as LAN Direct, IPv6 Direct, IPv4 server-reflexive, or learned peer-reflexive P2P. Symmetric/restricted NAT may remain on SFU; this is correct and must not interrupt audio. Block peer-to-peer UDP while leaving UDP 9001 reachable to verify fast SFU fallback.

Unit and integration tests cover packet codecs, continuous qualification, reset on bad samples, full-room matrix gating, temporary Hybrid joins, fast degradation fallback, source binding, subscriptions, room isolation, and SFU forwarding.

## Known V0.3 limits

- This is an ICE-inspired protocol, not full ICE/STUN/TURN or WebRTC compatibility. It borrows frp XTCP's assisted-address, repeated-strategy, endpoint-learning, and relay-fallback ideas without its broad random-port scan, which is a poor fit for a realtime voice client.
- Relay and SFU share one UDP listener and differ by route policy; there is no TURN allocation protocol.
- Congestion control, adaptive Opus bitrate, FEC, E2EE upgrades, multi-region media nodes, and Top-N forwarding remain future work.
- NAT rebinding triggers candidate republishing and requalification; seamless interface handover is best-effort rather than a mature multipath implementation.
