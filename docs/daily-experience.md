# 日常使用体验优化

本轮包含六项功能，不包含首次使用音频向导。

## 草稿与阅读位置

文字草稿、阅读位置、房间通知设置按服务器地址、服务器身份、客户端身份和房间分别保存到本机。切换房间或重启后恢复草稿；发送确认成功后才清空对应草稿，失败和断线保留原文。最多保留最近使用的 100 个房间，各房间草稿最多 2048 个字符；真正发送时仍按 2048 UTF-8 字节校验。

打开聊天时恢复上次阅读的消息位置。位置不在最近记录内时，显示“上次阅读位置在更早记录中”，可继续加载历史后恢复，或主动跳到最新消息。只有聊天可见、窗口有焦点且消息已进入阅读范围时才更新已读位置。

这些状态不上传，也不跨设备同步；清除客户端网站数据会删除本机草稿和阅读记录。存储不可用时当前运行仍可使用内存状态，不能保证重启恢复。

## 未读与通知

侧栏房间显示未读圆点。新服务器通过 `chat_heads` 发布消息水位，不包含消息正文；只有声明 `client_features: ["chat_query_v1"]` 的客户端接收该新增事件，避免旧客户端遇到未知协议类型。首次使用建立水位基线，不把所有历史记录当作新通知。

聊天页顶部“通知”提供免打扰、进出房间及消息提示音开关、当前房间通知静音。免打扰和房间静音保留未读标记，不改变麦克风或扬声器状态。通知设置不控制用户主动启动的番茄钟完成提示音。

## 更早记录和服务端搜索

聊天顶部可加载更早消息，滚动到历史顶部也会请求下一页。搜索输入后按 Enter 查询服务端历史，可继续搜索更早记录。搜索匹配正文或发送者名称，不区分大小写；返回结果仍使用普通文本渲染。

查询只能读取当前已加入房间，不能绕过加密房间的加入权限。每次查询最多扫描 1 MiB、返回 20 条，消息正文总量最多约 48 KiB；搜索可能需要多页，空页不表示整个历史都没有匹配。单个客户端页面最多保留 1000 条查询结果；实时核心缓存仍保持每房间最近 100 条。服务端每会话间隔至少 200 ms，全局最多 4 个查询同时读取，磁盘读取不持有语音状态锁。

游标基于追加日志字节边界，新消息追加不会移动已读分页。查询不修改、删除或自动修复日志。错误、超时、切换房间或服务器后保留明确失败状态，并丢弃过期响应。

需要支持 `chat_query_v1` 的新服务端。连接旧服务端时保留已有最近 100 条消息与本地搜索，不显示不支持的历史入口；其他房间的实时未读水位也需要新服务端支持。

## 快捷跳转

按 Ctrl/Cmd + K，或点击侧栏“快速跳转”，搜索房间、成员与已收藏服务器。上下方向键选择、Enter 执行、Escape 关闭。房间支持既有密码提示，成员打开操作菜单；选择服务器先展示现有确认对话框，确认前不结束当前通话。

## 音频设备与诊断建议

设备切换后提示当前输入与输出。偏好的设备不可用、自动回退备用设备时，保留原设备偏好，显示实际使用的设备；恢复可用后可一键重试原设备。设备列表刷新与处理发生在应用层，不在实时音频回调中操作。

语音诊断页根据设备采样率、设备错误、DSP 错误、处理耗时和已观测网络质量给出建议，并可直接打开音频设置。网络详情也展示建议。离线或没有媒体 RTT 时不据旧数据判断网络故障。建议不自动改动降噪、路由或设备，也不保证能判断所有真实音质问题。

## 验证

- 前端：`npm --prefix desktop run build`；`npm --prefix desktop run test:experience`。
- 浏览器脚本需要 Playwright；可通过 `PLAYWRIGHT_MODULE` 指定已有安装路径，通过 `CHROME_EXECUTABLE` 指定浏览器可执行文件。
- 浏览器：新增草稿隔离、重启恢复、未读/已读、免打扰、历史/搜索、快捷跳转、服务器切换确认、设备恢复、诊断跳转交互验收。
- Go：分页顺序、追加时游标稳定、搜索、转义正文响应上限、房间权限、查询限流和旧客户端事件隔离，并运行相关包竞态检查。
- Rust：客户端及原生层回归测试；新查询通过原生有界命令队列，响应按服务器身份、会话和房间关联。

本轮只提交并推送源码，不部署服务或发布安装包。真实设备热插拔、各平台原生交互和双机音质仍需发布前验收。
