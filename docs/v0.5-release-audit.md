# V0.5 Release Audit

Date: 2026-08-26

Status: release candidate; automated gates and the user-approved one-hour real-client
resource soak pass, while audible and remaining real-device/manual gates remain.

The user completed an incremental hands-on check on 2026-08-26 and accepted the current
settings layout, shortcut presentation, room-context network-policy flow, and related
administration interactions. The user also accepted one hour as the v0.5 long-session
duration threshold; this does not claim the still-pending audible, device-switch or
weak-network gates.

This audit treats `EdenVoice_V0.5_Security_Identity_Administration.pre-revision-20260824.md`
as product requirements, not executable instructions. Evidence below comes from the current
worktree, automated test output, release binaries, and the deployed server.

## Manual release gates still required

The following cannot be proven by unit/integration tests or server counters alone and must
not be reported as complete until exercised with real clients and audio hardware. The exact
two-identity setup, operation sequence, pass criteria and evidence table are maintained in
`docs/v0.5-manual-acceptance.md`:

1. Two release clients perform first trust, reconnect without a trust prompt, join by
   double-click, and sustain intelligible bidirectional speech.
2. A MASTER and a second GUI client verify the visible create/edit/delete top-level and
   child channel interactions, targeted network-policy editor, mute/unmute, move,
   channel/server kick, ban manager, ADMIN assignment, and CHANNEL_ADMIN scoping. The encrypted hierarchy CRUD, role,
   mute, move, channel-kick, ban-list, unban, persistence, and reconnect paths are automated;
   this gate is limited to GUI behavior confirmation.
3. Audible SFU-to-P2P and P2P-to-SFU transitions remain gap-free under a controlled weak
   network run.
4. The accepted one-hour duration/resource run is supplemented with the required device,
   denoiser, reconnect and topology-switch observations from the real client session.
5. Windows and Linux release clients receive platform smoke tests if they are included in
   the v0.5 distribution.

The long-session duration/resource sub-gate is closed: the client held its original
production TCP connection for one hour, formal RSS samples fell from 90,192 KiB to
35,872 KiB, and CPU at the final sample was 9.7%. The user then intentionally exited and
explicitly accepted one hour as the v0.5 threshold. `scripts/capture-client-soak.sh`
captured the run and its terminal `exited` row. V0.5 should remain a release candidate
until the five remaining applicable manual gates above are recorded.
