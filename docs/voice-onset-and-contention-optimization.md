# 20 ms 起音缓存与收发锁竞争优化

本次基于 v0.8.0，针对语音活动输入的轻声起音，以及注册、探测、换钥与语音收发的锁竞争。协议、自动码率和服务端配置不变。

## 起音缓存

- VAD 未开门且允许发送时，只保存最近一帧处理后的 PCM（960 个采样，48 kHz，即 20 ms）。
- VAD 开门时，先编码发送这一帧，再立即编码发送当前帧。持续说话不会进入额外等待队列。
- 静音、麦克风测试、PTT 模式、DSP 处理器更换和过期帧会清空缓存；清空前已采集的排队帧不能重新进入缓存。相邻采集时间差达到 40 ms 时，不跨越缺帧补发。
- 20 ms 指保留的音频长度，不是每次发包前固定等待 20 ms。补发仍可能改变接收端播放队列和起音时序，不能承诺口到耳延迟绝对不变。超过一帧的低于门限起音也不能全部恢复。

## 收发竞争

- SFU 音频、注册和服务器探测使用同一已发布的只读发送密钥快照，不再占用控制侧 outbound cipher 互斥锁进行加密。获取快照只短暂持有读锁，HKDF 和加密均在锁外完成；换钥发布只替换快照。
- 发送序号仍由会话共享的原子计数器分配，设备重启不重置；接收端继续使用原有共享防重放状态、认证及换钥宽限窗口。
- 换钥 HKDF 移出接收加密锁，安装前检查基础 epoch 未改变。
- SFU 收包不访问 P2P 路由锁；周期路由探测、上下文清理和指标发布遇到忙锁时延后，探测跳过不会上报虚假的路由降级。P2P 来源校验继续保留。
- 这不是整个通讯链路无锁化，也不取消过期帧丢弃和 UDP 错误处理。

## 验证

- 客户端全部目标：280 项通过，3 项按原配置忽略。
- 客户端和桌面 Rust 全部目标严格 Clippy（`-D warnings`）通过。
- 新增起音单帧上限、连续语音、静音/PTT、过期缓存测试；新增换钥快照、篡改认证、防重放及旧密钥过期测试。
- 持续占用路由、配置和发送控制锁，跨多个探测周期验证 SFU 加密双向通讯；原发送锁占用测试改为要求发送成功，而非允许丢帧。
- 多人加密全互联基准第一次与全部测试并行执行时出现 P2P 转 Hybrid 断言，后续隔离复测结果见下方。不能单凭回环基准替代真实麦克风、扬声器和系统负载下的听感验收。
- 隔离复测：2 人和 6 人各 3 轮，总计 19,200 次帧交付全部收到，重复交付为 0；6 人每轮稳态发送 P99 为 0.944 / 0.982 / 1.051 ms，冷启动最慢 6.396 ms。6 人每轮有 4 / 3 / 4 个 SFU 保护或回退发送，未造成重复交付。以上是本机 debug 加密 UDP 回环测试，不是口到耳延迟。
