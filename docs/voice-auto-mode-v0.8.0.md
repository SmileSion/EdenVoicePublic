# V0.8.0 自动语音模式优化

## 行为变化

- 调档防抖按至少 500 ms 间隔推进，多人同时上报不会把同一时刻的反馈当成多次稳定观测。超过 1.5 秒未推进的候选重新累计；严重恶化仍可立即降档，恢复仍保留 2 秒保持时间和 4 个有效观测。
- 接收端不再发送零流量窗口；不足 5 个成功接收包的无损窗口也不用于证明恢复。少量但确实发生的丢包仍会上报。QoE 增加可选 `observed_packets`，服务器原样转发；新发送端不会用不足样本的反馈推进恢复。切换房间质量设置也不再生成虚假的健康样本。
- 正在播放的语音升高缓冲目标时不再停播重新预填。使用波形对齐、2.5 ms 交叉渐变，每 5 个播放帧最多扩展一次，逐渐增加安全余量。初次起播和真实空缓冲后的预填继续保留，丢包的 FEC/PLC 继续工作。
- 客户端、桌面应用、界面、更新比较默认版本和服务端程序版本统一为 0.8.0，锁文件同步。已发布下载链接及历史版本文档保持原值。

## 混合版本

`observed_packets` 为可选字段，旧反馈仍能解析，旧服务器也能处理新反馈。新客户端即使经过旧服务器仍会在源头抑制空闲窗口，但旧客户端产生的无样本反馈缺少明确标记，无法完全消除其误判；完整的有效样本判断需要收发端和服务器均升级。网络及媒体封包格式未改变。

## 验证

- 客户端全部目标测试：272 项单元测试、1 项 UI 集成测试、3 项示例测试通过；默认忽略项未运行。
- 新增多人反馈、防抖时间间隔、空闲及稀疏窗口、QoE 样本门槛、连续语音缓冲增长、波形连续性测试；更新原来要求升档停播的测试。
- 客户端、桌面端严格 Clippy `--all-targets --offline -- -D warnings` 通过。
- 桌面前端 `npm run build` 通过。
- 服务端 protocol、voice、serverstate、control、voice-server 的 Go race 测试通过，覆盖有效包数量的转发和语音封包。原零分配断言失败已修复：AppendBinary 显式复用足够容量，容量不足才分配并保留前缀，不再依赖 race 模式禁用的 append/make 编译优化。保留零分配断言并增加容量不足的回归测试；普通与 race 模式的复用基准均为 0 B/op、0 allocs/op。
- 未打安装包、推送或部署；真实设备和公网弱网的主观听感仍需验证。
